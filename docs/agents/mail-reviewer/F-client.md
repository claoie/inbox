# §F.client — Client / UI / browser

Load when the diff touches `src/client/**` or any user-facing rendered surface.

- **Iframe/content reflow on fold-unfold: drive it off the native `toggle` event, not a body-click + `setTimeout` heuristic** — `MailBody.tsx` replaces a quoted-reply blockquote with a native `<details>` for fold/unfold and resizes the mail iframe to fit. The original code queued `adjustMailContentSize` ~50ms after every body click, which (1) missed KEYBOARD activation of `<summary>` (Enter/Space toggle `<details>.open` but fire no body click → no reflow) and (2) raced slow renders/image-loads inside the blockquote (timer fires before `scrollHeight` settles). Correct shape (PR #627): attach a per-`<details>` `toggle` listener after the blockquote→details swap — native `toggle` fires AFTER the browser applies `open` and lays out the slotted content, so the in-handler `scrollHeight` is correct for every activation method. Flag any "measure N ms after a click" pattern for content whose size changes via a native control. **Cross-browser caveat (PR #628): iOS Safari can suppress `toggle` reaching the handler** — add a `ResizeObserver` on the iframe body as defense-in-depth, with a `suppressResize` flag + two-rAF wait to avoid a measure→`height:auto`→body-shrinks→re-fire recursion loop (the body has `height:100%` from `processHtmlForViewer`). Watch for >1 reflow path firing per toggle (body-click + `toggle` + ResizeObserver) — consolidate or it's wasted measurement passes.
- **No unbounded blobs in `localStorage` / `useLocalStorage` — persist a reference (ID + small metadata), re-fetch the payload** — `localStorage` shares one ~5MB per-origin quota across ALL keys; a single large value throws `QuotaExceededError` on `setItem`, and because that write usually sits inside a React setter it crashes the component that mounted it. Flag HIGH any `localStorage.setItem` / `useLocalStorage` whose value is HTML, a mail body, base64, a rendered document, or an unbounded accumulating array. Correct shape (inbox #668/#669, 2026-07-11): `Writer/index.tsx` persisted the full quoted original-message HTML under `originalMessage` and blew the quota in prod → the quoted HTML moved to `useState` (not persisted) and only `originalMessageMeta = {id, messageId, subject, prefix}` (small strings) stays in `localStorage`; on mount the writer re-fetches `/api/mails/body/{id}` and re-wraps the quote. Reference-in-storage, blob-resolved-on-demand. Large structured client state belongs in IndexedDB, not `localStorage`; any `setItem` that could carry user-sized data wants a `try/catch` for `QuotaExceededError`.
- **UI placement change must not tighten gating** — when a diff moves a control INTO an existing conditional block, the block's outer gate (account-type, role, feature flag) silently becomes the moved control's gate. If the control was visible in states the new gate excludes, flag MED: pre-existing entities in those states are now orphaned — the row may still render in lists but the detail-page control to toggle the state OFF is gone. Safe shapes: (a) lift the row out of the outer gate while keeping it visually adjacent, or (b) gate the moved row on `(outerCondition || currentState)`. When reviewing a placement change, name what states were reachable before and confirm they're still reachable after.
- **Optional visual prop must render conditionally** — when a row component accepts an optional `color`/`icon`/`badge` prop and the rendered DOM contains an element styled by it, wrap the element in `{prop && <div…>}`. An empty `<div style={{backgroundColor: undefined}}/>` still takes layout space and reads as indentation. Flag any diff that renders a styled decorator unconditionally when the value driver is optional.
- **Composability of overlapping boolean toggles** — when a PR adds a second boolean control to an entity that already has a related one (Spam/Allowlist, Mute/Snooze, Disable/Pause), the dependent one must `disabled={dominantBoolean}` so its row can't fire mutations whose effect is invisible. Flag any diff that ships overlapping toggles without explicit precedence + disabled wiring.
- **New visible UI surface (banner, modal, dialog, toast, dropdown) must match the dark theme** — flag any diff adding a new visible element whose colors are hardcoded (`#fff`/`#000`/light literals) rather than sourced from the app's theme tokens/CSS variables. The maintainer catches this reflexively: same day (2026-07-01) they flagged #638's offline banner (*"Is this banner dark themed?"*, CHANGES_REQUESTED) AND #623's allowlist modal (*"Change the color of modal to match dark theme"*). The PR's E2E evidence must include a dark-mode screenshot of the new element.
- **Dead UI path + direct-URL E2E masquerading as UI-driven** — flag any interactive control gated behind a prop with a falsy default that NO caller in the diff/codebase sets truthy: the surface behind it is unreachable in the real UI, so any "verified" claim about it is untested. And when a PR's test plan claims UI-driven verification of a surface, require it to name the click path (row/link/button → navigation); treat any `page.goto(<detail/edit URL>)` in the E2E as NOT UI verification for that surface — the affordance must be wired and clicked, or the surface reported unreachable. The anti-pattern applies to any client PR.
- **Text-assertion / measurement-only E2E is NOT visual verification — a UI PR's test plan must include a mobile-viewport screenshot the author actually LOOKED at** — flag any UI-touching PR whose test plan proves only string content, persisted values, or a `getBoundingClientRect`/computed-style measurement grid, with no screenshot at the maintainer's reported viewport (~390×844 iOS Safari) that a human eye-checked. Layout, formatting, and affordance are DISTINCT dimensions text/measurement can't reach: a content grep passes whether the text sits at pixel 30 or 200; a value check passes whether an input shows a formatted string or a bare token; a distinguishable-affordance question (can a user tell an editable field from a read-only span on the dark background?) is invisible to `input.count()>0`. And `getBoundingClientRect` measures CONTAINERS, not glyph positions — an inline-block input can leave a large visible gap inside a container whose box ends uniformly, so the grid reads green while the render is broken. Require the test plan to: screenshot at ~390×844, Read/eye-check it, describe what's literally visible, and — when measurement passes but the render looks off — TRUST the render. The rule applies to any UI PR (dark-theme banner/modal contrast, formatting, alignment).
- **Client call must be typed against the route's real request/response shape** — flag a `fetch`/mutation whose body object or response read is hand-rolled rather than typed off the route's published request/response type from the server barrel, especially with a catch-all else that relabels every failure as one domain message. A field-name or wrapper-shape mismatch then compiles but fails at runtime with a misleading user-facing error.
- **A read-time sanitizer on persisted state that isn't written back to storage leaves every later guard on that value unreachable.** Flag any `useLocalStorage`/`useState(() => …)` initializer that TRANSFORMS a persisted value without persisting the transform, and flag any mount-effect/guard whose condition tests a value such an initializer has already normalized — that branch is dead on arrival. inbox #786: PR #273 added a `sanitize` arg coercing `selectedCategory: Search → AllMails` at read time; PR #278 one day later added `useEffect(() => { if (selectedCategory === Category.Search) { …; setSelectedAccount(""); } }, [])` to clear the *other* half of the state (the search term parked in `selectedAccount`). The sanitizer had already made that condition permanently false, so the reset never ran once — issue #276 was closed by a fix that has never executed, and the bug stayed live 4 months (reload while searching → app stranded on a phantom account, "No emails in this account.", reproduces every reload). Three sub-rules: (a) a reviver must write the normalized value BACK, or storage and state permanently disagree; (b) two keys encoding one logical mode must be reset in ONE place — a PR that clears one and trusts a separate mechanism for the other is the smell; (c) a "state resets on reload" test must assert on `localStorage` after the reload, not just the rendered view — asserting the rendered category alone is what let PR #278 pass review. Also flag closing-an-issue-as-fixed with no failing-then-passing test or live repro.
- **Never clear a client cache speculatively — the clear sits AFTER the success branch of the fetch that replaces it.** `clear → fetch` shows an empty UI for the whole round-trip and, on fetch failure (network drop, 500, expired session), permanently destroys the only fallback. Correct order: fetch → on-success swap in the new data → then clear/replace the cached copy; on failure keep the cache and surface a sync error. Flag any `indexedDB.deleteDatabase`/store-clear, `caches.delete`, `localStorage.remove*`, or `setData(null)` that runs before its replacement data has arrived. Carve-out: security-driven wipes (logout, role change) may clear unconditionally, but still after their own confirmation step.
